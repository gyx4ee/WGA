# Актуализации от wsga.eu с отделни файлове

Адрес за проверка: `https://wsga.eu/updates/wga/version.json`.

WGA изтегля JSON manifest и след това само файловете с различен размер или
SHA-256. Файловете се проверяват във временна папка. Работещото приложение
се затваря чак след успешното изтегляне и проверка, след което helper заменя
файловете и рестартира WGA. Настройки, лицензи и папката Installers се запазват.
Няма WGA-portable.zip за качване. Вътрешният `base_library.zip` е част от Python
runtime-а и трябва да остане сред файловете на приложението.

## Първоначално преминаване

Версии до 0.2.68 разбират само ZIP актуализации. Последната GitHub актуализация
0.2.69 е преходен ZIP за тях: потребителят натиска „Провери за нова версия“ и
инсталира актуализацията по досегашния начин. Вътре в пакета адресът вече е
wsga.eu; след рестартиране WGA проверява само новия сървър.

GitHub `version.json` остава с адрес към преходния ZIP, а `version.json` вътре
в приложението и на хостинга сочи към файловия manifest на wsga.eu.
Не заменяй GitHub metadata с hosting metadata: старите клиенти не разбират manifest.

Алтернативно затвори WGA и копирай съдържанието на `dist/0.2.69/WGA/` върху
инсталираната папка. Запази Installers и личните настройки. Само смяната на адреса
в стар version.json не е достатъчна: старото EXE няма логика за отделни файлове.

## Следваща версия

От папката на проекта изпълни, като промениш номера и описанието:

```powershell
python tools/prepare_wsga_release.py --build --version 0.2.70 --notes "Описание на промените"
```

Командата прави portable билд и подготвя `hosting-upload/updates/wga/`.
Не прави Setup EXE, ZIP, Git commit или качване.
Нужни са Python, PyInstaller и зависимостите на WGA на машината за билдване.

## Ръчно качване

1. През FTP/SFTP/File Manager качи `hosting-upload/updates/wga/releases/НОМЕР/`
   в `public_html/updates/wga/releases/НОМЕР/`. Изчакай всички файлове.
2. Качи `.htaccess` в `public_html/updates/wga/`, включително скритите файлове.
3. Качи `version.json` **последен**, след всички release файлове. Най-добре го
   качи като `version.next.json` и го преименувай на `version.json` на сървъра.
4. Отвори `https://wsga.eu/updates/wga/version.json` и провери номера.
5. В WGA натисни „Провери за нова версия“ и тествай на отделно копие.

Не презаписвай публикувани release папки: всяка нова версия има нов номер.
Запази старите release папки за клиенти, започнали изтегляне преди новото качване.

## Видимост и хостинг

За Apache/LiteSpeed включеният `.htaccess` използва `Options -Indexes`.
Отварянето на папката връща Forbidden, но конкретните файлове остават достъпни
за updater-а. Това скрива списъка, не е защита срещу човек, който знае адреса.
Ако хостингът не разрешава Options в `.htaccess`, изключи directory listing от
контролния панел или поискай настройката от доставчика.

За Nginx администраторът задава `autoindex off;` за `/updates/wga/`.
Изключи кеширане за `version.json`, разреши HTTPS и изтегляне на `.exe`, `.dll`,
`.pyd`, JSON и файловете под `_internal`. WAF не трябва да показва CAPTCHA.
При Laravel сайт сложи `updates/` в публичната директория на сайта.

Преди файловете да са качени на реалния хостинг, новият адрес няма да работи.
Не е нужно да качваш целия изходен Python проект или личните си ключове.
